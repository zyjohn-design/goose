## 视觉方向

大方、庄严、易读。使用暖白画布、白色内容卡片、深灰文字，以政务红强调主要操作与选中状态，金色仅用于少量装饰。保留 Goose 的配方、技能、应用、调度、扩展和会话结构，用适合政府办公的文字解释功能。

设计图是视觉参考，文字、颜色、间距和交互的实现以本说明及 `tokens.json` 为准；生成图可能存在局部字形和间距误差。

- 字体：优先系统中文无衬线字体，`PingFang SC` / `Microsoft YaHei` / `Noto Sans CJK SC`。正文建议 16px，辅助文字至少 14px。
- 导航：桌面默认宽度 238px，图标 20–22px；选中项同时使用底色、竖线与文字强调。
- 内容：建议最大宽度 1280px，页面边距 32px，卡片间距 20px；窄窗口由三列降至两列、一列，保留滚动能力。
- 图标：复用项目已有 `lucide-react`；每个条目独立配置图标，不能只给栏目标题加图标。48px 图标容器配 24px 线性图标，圆角 10px；红、蓝灰、墨绿、赭金配浅色底。
- 图标缺失：按稳定条目 ID 查询图标注册表，再按资源类型提供通用图标；名称变更不应导致图标随机变化。外部图标失败后仍显示兜底图标，不能空白。
- 状态：启用/停用、连接/断开必须附文字或可读标签；焦点态、键盘操作、按钮标签和头像替代文字需在实现阶段覆盖。
- 品牌：使用抽象政务建筑符号，不直接将国徽或公章作为装饰。首页浅色乡镇风景为概念插画，正式上线前应替换为本镇授权素材或移除。

## 功能边界与交互

1. 配方：复用现有创建、导入、编辑、使用流程。分类筛选和收藏为规划交互，需要新增数据持久化。
2. 技能：当前代码主要读取技能名称及说明；设计中的逐项启停、分类、收藏和导入能力应先核对后端支持，再实现，不能用只改样式的开关伪装生效。
3. 应用：复用实际 MCP 应用的导入、启动、导出及删除；会议日程、公文助手等仅是卡片内容示例，不表示已存在业务系统。
4. 扩展：沿用现有扩展配置及启用流程。区分“为新会话默认启用”和“当前会话启用”；连接状态及工具数量从实际结果读取，不能以开关值代替连通性检测。
5. 首页：输入、附件、模型选择、工作目录和发送行为继续对接 Goose；“政务大模型”仅为展示占位，不代表预装或认证模型。
6. 账户：新增“个人账户”区域，显示头像、姓名、部门、单位与登录状态；另保留“模型服务凭据”。现有 Provider Credentials 管理的是模型凭据，不能视作人员登录。
7. 登录：单位统一认证、头像上传、资料保存及退出登录需要真实身份服务和会话生命周期。未接入时显示“未登录/待配置”，点击登录不能只切换一个本地布尔值。权限由服务端校验，UI 不作安全承诺。
8. 调度与历史：本轮没有单独出图，保留现有路由和功能，后续沿用同一设计系统。
9. 空态/加载/错误：各中心分别提供带图标的空态、卡片骨架、搜索无结果与可重试错误；图片中的示例内容不作为默认业务数据写入生产环境。

## 后续开发顺序与验收

1. 实现主题、布局和通用资源卡片，将四类资源的图标渲染与兜底统一起来；保留 i18n 文案机制。
2. 依次改造工作台、配方、技能、应用和扩展页面，使用实际数据并覆盖空态、加载、错误和窄窗口。
3. 增加个人账户设置和侧栏账户区域，对接确定的单位认证服务，再实现资料保存和退出。
4. 在现有功能上验证配方启动、应用启动、扩展配置、会话切换与模型设置没有回归；对新增权限与认证行为做专项验证。

本次交付仅为 PNG、设计说明、视觉参数、图标建议和本地预览页，不需要安装 Electron/Rust 依赖。预览页无外部脚本和网络请求，登录、保存、调用工具均不在预览页中执行。
